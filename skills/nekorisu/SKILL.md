# nekorisu

nekorisu 把会话原样存到用户自己选的存储里，需要时按行读回来，或者原样放回 Agent 的目录接着做。它只搬运、校验、记录；理解和总结由你来做。

## 工具

| MCP 工具 | 做什么 |
|---|---|
| `scan` | 本机有多少会话、多大 |
| `status` | 每个会话多了什么、上次上传是多久前、会不会快被 Agent 自己清理 |
| `search` | 按关键词、时间、设备、Agent 找会话 |
| `fetch` | 读一个会话：按行号，或按种类（`user` 人说的话、`assistant` 回复、`reasoning`、`tool`、`meta`）；`max_field_chars` 限制每个字段的长度；`whole` 整份下载到本地并返回路径 |
| `restore` | 把会话原样放回 Agent 原来的目录，然后告诉用户 resume 命令 |
| `archive` | 上传会话（子 Agent 的会话一起），可以附带 digest |
| `digest` | 读、写、改 digest |
| `log` | 追加或查看整理记录：标签、备注、"这几个会话是同一件事" |

每个工具都有同名的 CLI 命令：`nekorisu <命令>`。

## 你自己决定的

- 什么时候读 digest、什么时候取几行、什么时候整份下载。顺序：先读 digest，再 `fetch` 用户说的话，确实需要再取更多。能少取就少取，长字段用 `max_field_chars` 截短。
- 按本 skill 写 digest。

## 先问用户的

- 上传、恢复、删除本机原件：用户说了才做。上不上传、删不删本机原件，由用户决定。
- 拿不准的地方，比如这几个会话是不是同一件事。
- 存储的密码：推荐用户自己在终端里运行 `nekorisu storage login <名字>` 输入。不要主动让用户把密码发给你；用户坚持要给你，照用户说的做，不替用户做决定。

## 翻旧账

1. `search` 找候选会话。
2. 有 digest 就先读 digest。
3. 没有，就 `fetch(kinds=["user"])` 只取用户说的话；要上下文再按行号取前后几行。
4. 用户想原样接着做：`restore`，然后把 resume 命令告诉用户。

## 整理并上传

用户说"整理一下传上去"时：

1. `status`：列出还没上传、或上传后又有新内容的会话。
2. 按下一节写 digest；拿不准就问用户。用户不要 digest 就不写。
3. `archive`，附上 digest。整理记录用 `log` 追加。

## digest 写什么

要写：

- **用户的每一句原话**，原样照抄，不复述、不改写、不概括。只收人说的话：主 Agent 写给子 Agent 的任务说明、自动注入的环境信息都不算。
- **每句原话回应的那条 Agent 回复**，和原话放在一起。通常是用户说这句话之前，Agent 的最后一条回复。
- **每一轮的数据**：和上一句隔了多久；这一轮派生了多少 Agent、多少模型轮次、平均 prompt、平均缓存命中、新增多少思考、长度。
- **关联的子 Agent 会话**：写在主会话的 digest 里。

不写：

- Agent 的中间过程：工具调用、命令输出。
- 这份 digest 是谁写的。

主观的部分（比如总结）写错了，直接改，替换掉原来的内容。写 digest、做整理，都不改已经上传的会话。

## 还没有规定的

- digest 有几种、每种写什么，以及具体的文件格式。
- 第 3 条里的每个数怎么算。算不出来就留空，不要估。
